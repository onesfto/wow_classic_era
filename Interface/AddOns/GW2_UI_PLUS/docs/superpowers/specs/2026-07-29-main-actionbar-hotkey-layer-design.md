# 主动作条快捷键原生与代理切换设计

## 目标

在不修改 GW2_UI 原生插件的前提下，修复主动作条快捷键文字被快捷键黑色背景遮盖的问题。

## 范围

- 仅修改 GW2_UI_PLUS。
- 仅处理主动作条中同时具有 `HotKey` 与 `hkBg` 的按钮。
- 快捷键位于“下”时保留 GW2_UI 原生文字和黑色背景。
- 快捷键位于其他位置时使用 PLUS 代理文字并隐藏黑色背景。
- 不改变其他动作条、宏名称或按钮图标的绘制层级。

## 方案

GW2_UI 原生主动作条直接使用 `button.HotKey`，并让 `hkBg` 围绕该文字定位。PLUS 当前始终创建代理文字、把原生文字设为透明并移动 `hkBg`，破坏了原生文字与背景的配套关系。

PLUS 改为按位置切换：

- `BOTTOM`：不使用代理显示，恢复原生 `HotKey` 的透明度、位置、字体和显隐；背景继续由 GW2_UI 原生逻辑管理。
- 其他六个位置：原生 `HotKey` 保持透明，由代理文字显示自定义位置，同时隐藏 `hkBg.texture`。

背景的 `Show` 后处理只在当前位置不是 `BOTTOM` 时再次隐藏，因此 GW2_UI 刷新不会让其他位置的背景重新出现；切回 `BOTTOM` 后不会阻止原生背景显示。

主动作条快捷键不得安装“原生文字永远透明”的通用代理钩子，否则从其他位置切回 `BOTTOM` 时无法恢复原生文字。宏名称和其他动作条继续沿用现有代理实现。

GW2_UI 源码与资源均不修改。

## 验证

- 删除 `tests/ActionBarLayout_test.lua`，不再保留与实际经典旧世渲染行为不一致的模拟测试。
- 运行剩余动作条测试与 Lua 语法检查。
- 游戏内验证 `BOTTOM` 使用原生文字和背景，其他六个位置只显示代理文字且没有背景。
- 验证从其他位置切回 `BOTTOM` 无需重载即可恢复原生文字和背景。
- 检查最终差异只包含 GW2_UI_PLUS 内与本问题直接相关的文件。
