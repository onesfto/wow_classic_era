# 插件悬浮按钮材质与布局优化设计

## 背景

GW2_UI_PLUS 已有独立的“插件悬浮按钮”功能，可以扫描小地图上的第三方插件按钮并收纳到 GW2_UI 的悬浮入口。当前实现只给按钮增加 GW2_UI 边框，没有清理第三方插件自带的圆形外框；所有按钮始终排成单行；入口还会被 GW2_UI 定位到小地图上方。

## 目标

- 功能开启时，所有被收纳的插件按钮统一使用 GW2_UI 小地图按钮材质。
- 清除第三方按钮外部的圆形边框、背景和高亮装饰，同时保留插件自身图标。
- 所有按钮统一为 `25 × 25`，图标向内缩进 2 像素。
- 每排最多显示 8 个按钮，超过 8 个后自动增加下一排。
- 悬浮入口默认固定在小地图右侧正中。
- 保持 GW2_UI 当前的点击、展开、收起、按钮顺序和展开方向。
- 关闭功能时，继续恢复按钮原来的父级、锚点、尺寸、缩放和层级。

## 实现设计

### 按钮换肤

扩展 `Minimap/AddonFlyout.lua` 中现有的 `SkinButton`。遍历候选按钮的纹理区域，并沿用 GW2_UI 原生 `minimapButtons.lua` 的判断方式：

- 已知的圆形遮罩、边框、背景、AlphaMask 和高亮纹理设为空或隐藏。
- 其余纹理视为插件图标，调整到按钮四边各内缩 2 像素。
- 将图标放到 `ARTWORK` 绘制层。
- 按钮尺寸设为 `25 × 25`。
- 使用 `GW.BackdropTemplates.DefaultWithSmallBorder` 创建 GW2_UI 背景和小边框。

每个按钮只执行一次纹理换肤，后续刷新只更新父级、位置和层级，避免重复创建边框或重复挂接悬浮高亮脚本。

### 八列换行布局

`UpdateButtons` 先收集当前可见按钮，再根据总数计算行数。每个按钮使用以下规则定位：

- 列号：`按钮序号 % 8`
- 行号：`floor(按钮序号 / 8)`
- 横向步进：27 像素，即 25 像素按钮加 2 像素间距
- 纵向步进：27 像素

首排最多 8 个，第 9 个从第二排开始。容器宽度根据实际列数计算，高度根据行数计算。多排在垂直方向围绕悬浮入口居中，保证入口位于小地图右侧正中时，展开内容不会整体继续向上偏移。

### 默认位置和交互

每次应用悬浮功能时，将 `GwAddonToggle` 锚定为：

```lua
GwAddonToggle:SetPoint("LEFT", Minimap, "RIGHT", 4, 0)
```

这会把入口放在小地图右侧正中，并覆盖 GW2_UI Classic 初始化时设置的顶部锚点。容器继续使用 GW2_UI 模板现有的相对锚点和展开方向，不修改点击脚本语义。

### 兼容性和恢复

- 候选按钮识别、战斗和宠物对战延迟逻辑保持不变。
- 不代理插件按钮，不替换其点击、提示或菜单脚本。
- 关闭功能时继续使用已有状态快照恢复按钮布局。
- 换肤属于功能开启后的统一外观，不在关闭时恢复第三方圆形装饰；按钮本身的位置、尺寸、缩放和层级仍完整恢复。

## 验证

扩展 `tests/MinimapAddonFlyout_test.lua`，先添加会失败的断言，再实现功能：

- 被收纳按钮尺寸统一为 `25 × 25`。
- 第 1 至第 8 个按钮位于首排，第 9 个按钮位于第二排。
- 容器宽高与实际列数、行数一致。
- 入口锚定在小地图右侧正中。
- 圆形或背景纹理被隐藏，插件图标使用 GW2_UI 内缩布局。
- 重复刷新不会重复换肤。
- 关闭功能后仍能恢复按钮原布局。
