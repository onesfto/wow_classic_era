# 框体菜单“目标的目标”拆分设计

## 目标

在 `GW2_UI_PLUS` 的“框体”顶级设置标签中，将当前合并在“目标”页面末尾的原生“目标的目标”设置拆分为独立菜单页。

拆分后的菜单顺序为：

1. 玩家
2. 目标
3. 目标的目标
4. 宠物
5. 小队

## 范围

- 删除把 `target_of_target` 设置项追加到 `target_general` 页面数据源的逻辑。
- 新增“目标的目标”菜单按钮，直接复用 GW2_UI 原生 `target_of_target` 设置页面。
- “目标”和“目标的目标”页面继续隐藏原生“隐藏器”分组。
- 保留原生页面、设置控件、getter、setter、依赖关系、回调和保存值。
- 小队页面保持当前状态，不过滤、不隐藏或修改任何设置项。
- `RAID_STYLE_PARTY_AND_FRAMES` 及其显示和行为均不处理。

## 实现方式

继续沿用 `MainMenu/MainMenu.lua` 现有的原生页面迁移机制：

- `PrepareUnitFrameSettings` 分别准备 `target_general` 与 `target_of_target`，只对两者调用现有的“隐藏器”过滤。
- 移除 `MergeTargetOfTargetSettings` 及其调用，避免修改目标页面的选项列表和滚动数据源。
- `BuildMainMenuTab` 在“目标”与“宠物”之间创建“目标的目标”按钮，并把它映射到 `target_of_target`。
- 页面切换仍通过 `CaptureFrame`、`RestoreFrame` 和 `SelectPage` 完成，不复制原生控件。

## 状态与兼容性

- 不新增 SavedVariables，也不迁移现有配置。
- 原生 GW2_UI 设置入口保持可用。
- 进入或离开 PLUS 的“框体”标签时，页面父级、锚点和显示状态继续按现有机制恢复。
- 如果必需的原生页面缺失，继续沿用当前行为：不创建不完整的“框体”标签，并输出一次提示。

## 验证

自动测试应验证：

- 菜单中存在独立的“目标的目标”入口，且位于“目标”和“宠物”之间。
- 代码不再调用或保留目标设置合并逻辑。
- `target_general` 与 `target_of_target` 都执行“隐藏器”过滤。
- 小队页面没有针对 `RAID_STYLE_PARTY_AND_FRAMES` 的新增过滤逻辑。

游戏内手工验证应确认：

1. “框体”菜单按“玩家、目标、目标的目标、宠物、小队”显示。
2. “目标”页面只显示原生目标设置，不再包含“目标的目标”设置。
3. “目标的目标”页面独立显示原生设置，且不显示“隐藏器”分组。
4. 两个页面中的设置均能正常保存并即时触发原生回调。
5. 小队页面与改动前一致。
