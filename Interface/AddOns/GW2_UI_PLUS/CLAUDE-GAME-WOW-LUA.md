# 魔兽世界插件开发 CLAUDE.md 规范

本指南专为开发魔兽世界（World of Warcraft）Lua 插件（尤其是经典怀旧服与硬汉模式）的 AI 代理提供行为准则与基准要求。

## 索引与阅读原则

- **强制前置阅读**：在开始开发任何魔兽世界插件功能前，必须先读取 `docs/DEV-GAME-WOW-LUA-GUIDE-GENERAL.md`，并严格遵守其中的架构与性能约束（如全局变量污染防范、硬汉模式的零容错标准、垃圾回收优化等）。
- **按需阅读**：如无必要，禁止在每次对话或操作时全量读取所有文档。仅当需要特定模块（如战斗日志解析、UI 界面更新）的详细信息时，再去检索相关代码或 WoW API 文档。

## 一、指令优先级

当多份规则同时存在时，按以下优先级执行：

1. 用户在当前对话中的明确指令。
2. 项目根目录的 `CLAUDE.md` 或本 `CLAUDE-GAME-WOW-LUA.md`。
3. `docs/DEV-GAME-WOW-LUA-GUIDE-GENERAL.md` 开发规范。
4. 暴雪魔兽世界官方 API 的安全与防污染约束（Taint Prevention）。
5. 代理默认行为与通用经验。

如果不同规则冲突，必须遵循优先级更高的规则，并在回复中说明冲突点。

## 二、语言规则

- 与用户交互必须使用中文，除非用户明确要求使用其他语言。
- 计划、问题、解释、总结、提交信息、PR 描述和文档内容默认使用中文。
- 游戏专有名词（如 Frame、OnUpdate、SavedVariables、Taint）、代码标识符、API 函数名应保持原始英文，不要生硬翻译。
- 如果项目已有代码注释语言约定，应遵循项目约定；没有约定时，新增注释使用中文。

## 三、基本行为准则

### 1. 先理解再行动
- 开始修改前必须理解用户目标（如是新增 UI 面板、解析特定 Buff 还是优化内存）。
- 可以通过读取 `.toc` 文件、搜索已有 Lua 代码、查看 `Embeds.xml` 来确认当前插件的基础架构。
- 对于不确定的 WoW API 行为（尤其是 60 级特有 API），应向用户确认或查询可靠来源，不能自行脑补（如误用正式服的 Focus API）。

### 2. 最小变更与防污染（Taint）
- 只修改完成任务必须修改的文件和代码。
- **绝不污染全局环境**：必须将所有新变量声明为 `local`，严禁未经允许创建新的全局表。
- 不做顺手重构、顺手格式化，除非它能显著降低硬汉模式下的卡顿风险（如清理高频 `OnUpdate` 中的冗余表创建）。

### 3. 保持现有风格
- 优先遵循项目已有目录结构（`Assets/`、`Libs/`、`Modules/`、`UI/`）、命名风格、事件注册方式。
- 如果现有模式明显无法满足需求（如存在严重的性能泄漏），应说明原因和替代方案，不可静默替换底层框架。

## 四、测试与发布红线

- **禁止未经确认的破坏性测试**：在硬汉模式下测试可能导致角色死亡。任何涉及战斗中动态修改界面的逻辑（如 `SecureActionButtonTemplate`）必须提前指出可能的报错和卡死风险。
- **发布构建要求**：严禁将含有高频 `print()` 或重度调试输出的代码直接合入主分支。
- **污染红线**：修改暴雪原生框架（如目标头像、动作条）前，必须确认是否会引发 Taint 导致战斗中无法点击。

## 五、任务执行流程

### 1. 接收任务后
1. 阅读用户请求，识别功能涉及的是视图更新、数据持久化还是战斗事件解析。
2. 检查 `DEV-GAME-WOW-LUA-GUIDE-GENERAL.md` 规范。
3. 搜索相关 Lua 文件和 XML 模板。
4. 对复杂功能（如编写新的预警模块）先给出简短计划。
5. 修改代码。
6. 提示用户进行 `/reload` 并在 `/console taintLog 1` 下验证。
7. 总结改动和剩余风险。

### 2. 复杂任务计划
当任务涉及跨文件状态共享、第三方库（Ace3 等）接入或复杂的 XML/Lua 混合开发时，应先制定计划。计划应包括：
- 涉及的模块（如 `Core/` 或 `Modules/`）。
- 全局与局部状态流向（与 `SavedVariables` 交互）。
- 性能评估（是否在 `OnUpdate` 中，频率多高）。
- 可能引发的 API 兼容性与原生 UI 污染风险。
