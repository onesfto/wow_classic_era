## 规范来源与术语

### 两套渲染器的列间距边界

设置页面使用两套布局渲染器，列间距规则不能混用：

| 渲染器 | 列间距 | 适用范围 |
|---|---:|---|
| GW2_UI 原生渲染器 | 固定 `8` 像素 | 原生设置页面，包括玩家的“增益光环”和“减益光环” |
| GW2_UI_PLUS 渲染器 | 默认 `0` 像素 | 动作条、工具条及其他 PLUS 页面 |
| 玩家 PLUS 页面 | `8` 像素 | 玩家子菜单中由 PLUS 重排的所有多列控件和按钮 |

玩家 PLUS 页面通过面板属性启用原生间距：

```lua
panel.gwPlusColumnGap = 8
```

没有设置该属性的 PLUS 页面继续使用无间距布局。列间距由渲染器统一计算，设置模块不得给单个选项手动增加额外偏移。

### 术语定义

- **页面**：一个设置面板，例如“框体 > 玩家 > 综合”。代码中通常是一个带 `GwSettingsPanelTmpl` 模板的 frame。
- **页面主标题**：页面顶部的大标题，例如“玩家”“动作条”。对应 `panel.header`。
- **页面小标题**：页面顶部的路径或当前子页面名称，例如“综合”“主动作条”。对应 `panel.breadcrumb`。
- **页面标题描述**：页面顶部小标题下方的说明句，例如“调整玩家框体的显示与尺寸”。对应 `panel.sub`。
- **分组标题**：页面内容区内的大分组，例如“尺寸”“位置”。使用 `AddGroupHeader()`。
- **子类标题**：分组内部的次级标题，例如“作用于哪些条”。使用 `AddSubGroupHeader()`。
- **选项**：一个实际设置项，例如开关、滑块、下拉框、文本输入。
- **控件行**：滚动区域中的一条布局记录。一个控件行可以承载一个或多个选项。
- **列数**：由 `option.gwPlusColumns` 指定的同一行选项数量。本文中的“单排、双排、三排、四排”统一解释为“单列、双列、三列、四列”。
- **主开关**：带 `isMasterToggle = true` 的页面总开关，通常显示为“启用”。
- **移动框体**：有 `gwMover` 的实际游戏框体，例如玩家框体、施法条、能量条。

## 页面层级

一个标准设置页面的视觉顺序如下：

```text
页面主标题       玩家                         20 号字体
页面小标题       综合                         12 号字体
页面标题描述     调整玩家框体的显示与尺寸。    12 号字体
────────────────────────────────────────────
内容滚动区域
    分组标题     尺寸
    选项         缩放
    选项         血条宽度
```

### 页面主标题

页面主标题说明当前设置属于哪个大类，不说明具体功能。推荐使用下列形式：

```lua
panel.header:SetFont(DAMAGE_TEXT_FONT or "Fonts\\FRIZQT__.TTF", 20)
panel.header:SetTextColor(GW.Colors.TextColors.LightHeader:GetRGB())
panel.header:SetText("玩家")
```

规则：

1. 主标题只出现一次，不能把功能描述塞进主标题。
2. 主标题使用 20 号字体。
3. 主标题使用 `LightHeader` 颜色，保持与 GW2_UI 原生页面一致。
4. 不要在主标题中加入过长的解释、版本号或默认值。

### 页面小标题

页面小标题表示当前页面在侧边菜单中的名称，例如“综合”“血球和贴图”“施法条”。

```lua
panel.breadcrumb:SetFont(DAMAGE_TEXT_FONT or "Fonts\\FRIZQT__.TTF", 12)
panel.breadcrumb:SetTextColor(GW.Colors.TextColors.LightHeader:GetRGB())
panel.breadcrumb:SetText("综合")
```

规则：

1. 小标题使用 12 号字体。
2. 小标题只写页面名称，不重复主标题。
3. 页面名称变化时必须同步侧边菜单名称、`panelId` 和 `breadcrumb`。
4. 小标题过长时应缩短名称，不要依赖换行破坏顶部高度。

### 页面标题描述

标题描述是页面顶部对整个页面的简短说明，使用 `panel.sub`。当前代码采用 12 号字体和 `181 / 255, 160 / 255, 128 / 255` 的暖灰色。

```lua
panel.sub:SetFont(UNIT_NAME_FONT or "Fonts\\FRIZQT__.TTF", 12)
panel.sub:SetTextColor(181 / 255, 160 / 255, 128 / 255)
panel.sub:SetText("调整玩家框体的显示与尺寸。")
```

规则：

1. 描述只说明本页面负责什么，不逐项解释设置。
2. 推荐一句话，长度控制在一行内。
3. 不在描述中写“点击这里”“请勾选”等操作教程。
4. 需要解释某个选项时，把说明放到 `AddOption(name, desc, values)` 的 `desc` 参数中。

### 选项标题与选项说明

选项标题是控件上直接显示的文字，通常使用 12 号字体。选项说明 `desc` 通过鼠标提示显示，并且会参与设置搜索；它不是页面中固定占位的正文段落。

```lua
panel:AddOption(
    "显示职业颜色",
    "使用职业颜色显示玩家名称。",
    {
        getter = function() return db.classColor end,
        setter = function(value) db.classColor = value end,
        getDefault = function() return defaults.classColor end,
    }
)
```

选项说明应包含：

- 这个设置改变什么。
- 是否只在某个开关启用时生效。
- 是否需要重载界面。
- 单位、取值范围或会影响的框体。

## 全局尺寸与行高

### 内容宽度

GW2_UI_PLUS 多栏渲染器使用以下固定尺寸：

| 尺寸 | 数值 | 说明 |
|---|---:|---|
| 有效内容宽度 | `550` | 所有单列和多列控件共享的总宽度 |
| 行左内边距 | `8` | 控件行左侧到第一个控件的距离 |
| 行右内边距 | `8` | 控件行右侧预留空间 |
| 行宽 | `566` | `550 + 8 + 8` |
| 标题后额外间距 | `8` | 分组标题或子类标题之后的选项间距 |
| 多栏计算方式 | 默认 `550 / 列数`；玩家页面按 `8` 像素间距计算 | PLUS 页面默认无间距，玩家页面显式采用原生列间距 |

对应实现：

```lua
row:SetWidth(566)
local gap = 0
local width = 550
if data.widgets then
    local columnCount = data.columnCount
    gap = panel.gwPlusColumnGap or 0
    local totalGap = gap * (columnCount - 1)
    width = (550 - totalGap) / columnCount
end
```

列起点使用 `8 + (column - 1) * (width + gap)`。因此，玩家页面的多列控件必须设置面板级 `gwPlusColumnGap = 8`，禁止在选项上直接按 `550 / 列数` 计算宽度或手动添加列偏移。其他 PLUS 页面不设置该属性，继续使用原有的等宽连续列。

### 行高

| 行类型 | 滚动行高度 | 控件实际高度 | 说明 |
|---|---:|---:|---|
| 普通选项 | `46` | `40` | 预留上下 3 像素的视觉空间 |
| 分组标题 | `40` | `40` | `AddGroupHeader()` |
| 子类标题 | `40` | `40` | `AddSubGroupHeader()` |
| 主开关 | `40` | 约 `24` 的内容区域 | 外层是 40 高，控件上下各留 8 |
| 单列按钮 | `40` | `24` | 上下各留 8 |
| 多列按钮 | `40` | `24` | 同样上下各留 8 |
| 主开关后的分隔行 | `5` | 分隔纹理约 `2` | 单独占用一条滚动行 |

普通选项的“行高 46”和“控件高 40”必须同时保留。不能把普通控件直接改成 40 高的滚动行，否则相邻选项会显得过于拥挤，且与标题后的间距规则不一致。

### 顶部间距

当某个普通选项紧跟在 `header` 或 `subHeader` 后面时，渲染器会额外增加 `8` 像素：

```text
分组标题       40
标题后间距      8
第一个选项     46
```

因此不要在选项描述、控件高度或 `SetPoint` 中重复添加同样的顶部空白。

## 标题、描述与分组样式

### 分组标题：`AddGroupHeader`

分组标题用于页面中的一级功能分组，例如：

```lua
panel:AddGroupHeader("尺寸")
panel:AddOptionSlider("缩放", nil, {...})
panel:AddOptionSlider("血条宽度", nil, {...})
```

当前模板的主要视觉尺寸：

- 行高：40。
- 标题区域：约 `600 x 25`。
- 标题左偏移：12。
- 标题垂直偏移：-6。
- 底部分隔纹理：约 `360 x 2`。
- 分隔纹理左偏移：12。
- 分隔纹理位于标题行底部下方约 5 像素。

当前模板的颜色和字体：

- 标题字体：`DAMAGE_TEXT_FONT`，16 号。
- 标题文字颜色：`GW.Colors.TextColors.LightHeader:GetRGB()`。
- `LightHeader` 的源码值：`CreateColor(1, 0.9450, 0.8196)`；按 8 位 RGB 约为 `(255, 241, 209)`，近似十六进制为 `#FFF1D1`。
- 标题文字阴影：黑色，透明度 1；这是设置控件的通用文字阴影，不要为分组标题另做一套阴影。
- 分隔纹理颜色：白色 `RGB (1, 1, 1)`，透明度 `0.65`。
- 左侧强调块颜色：白色 `RGB (1, 1, 1)`，透明度 `0.85`，尺寸约 `5 x 5`。
- 分组标题没有整行实色背景；可见的背景装饰仅包括分隔纹理和左侧强调块。

因此，分组标题的标准效果是“浅金色标题文字 + 白色半透明横线 + 白色小强调块”，不能把标题文字写成普通选项使用的纯白色，也不能为整行增加不透明色块。

规则：

1. 分组标题只表达类别，不放可操作设置。
2. 分组标题本身独占一行。
3. 分组标题不能设置 `gwPlusColumns`。
4. 分组标题之后的第一个选项自动获得 8 像素额外间距。
5. 如果一个页面只有三五个选项，不要为了填充空间强行增加多个分组标题。

### 子类标题：`AddSubGroupHeader`

子类标题用于一级分组内部的次级分类，例如动作条设置中的“作用于哪些条”。

当前模板的主要视觉尺寸：

- 行高：40。
- 标题区域：约 `560 x 22`。
- 标题左偏移：15。
- 标题垂直偏移：-2。
- 底部分隔纹理：约 `300 x 1`。
- 分隔纹理左偏移：15。
- 分隔纹理位于标题行底部下方约 5 像素。

当前模板的颜色和字体：

- 标题字体：`DAMAGE_TEXT_FONT`，14 号。
- 标题文字颜色：`GW.Colors.TextColors.LightHeader:GetRGB()`，即源码值 `CreateColor(1, 0.9450, 0.8196)`；按 8 位 RGB 约为 `(255, 241, 209)`，近似十六进制为 `#FFF1D1`。
- 标题文字阴影：黑色，透明度 1；沿用设置控件的通用文字阴影。
- 分隔纹理颜色：白色 `RGB (1, 1, 1)`，透明度 `0.45`。
- 子类标题没有左侧强调块，也没有整行实色背景。

子类标题与分组标题使用同一套浅金色文字，只通过字号、分隔线长度和分隔线透明度体现层级差异。

规则：

1. 子类标题不能取代页面主标题或页面小标题。
2. 子类标题也独占一行。
3. 子类标题下的选项仍然按照普通、双列、三列或四列规则排布。
4. 同一个子类中的选项应连续注册，不能被另一个分组插入。

### `groupHeaderName` 的含义

`groupHeaderName` 是选项的分组元数据，用于注册、搜索、依赖处理或刷新标识；它不会自动创建可见的标题行。

需要看到分隔标题时，必须明确调用：

```lua
panel:AddGroupHeader("尺寸")
```

只设置下面的元数据不会显示标题：

```lua
groupHeaderName = "尺寸"
```

## 启用主开关样式

### 主开关的定位

页面总开关使用 `isMasterToggle = true`，通常名称为“启用”。它负责控制当前页面对应的核心功能，不应和普通选项混在同一组中。

标准写法：

```lua
local enable = panel:AddOption("启用", "控制普通玩家框体是否显示。", {
    getter = function() return module:IsEnabled() end,
    setter = function(value) module:SetEnabled(value) end,
    getDefault = function() return true end,
    callback = function() module:Refresh() end,
    isMasterToggle = true,
})
```

### 主开关的布局

主开关必须满足：

1. 独占一行。
2. 有效宽度为 550。
3. 行高为 40。
4. 控件上下各保留约 8 像素。
5. 主开关之后，如果后面还有普通选项，立即插入 5 高分隔行。
6. 主开关前后不再额外插入重复的空行。

推荐的页面顺序：

```text
启用                                             独占一行
分隔底条                                         5 高
显示背景材质 | 显示职业颜色 | PvP 指示器          三列
```

### 主开关的视觉样式

当前 GW2_UI_PLUS 在原生开关控件上追加了两层纹理：

| 元素 | 尺寸或位置 | 状态 |
|---|---|---|
| 标题 | 12 号字体 | 使用 `LightHeader` 颜色 |
| 背景高亮 | 高 `24` | 最小宽 `80`，最大不超过标题宽度加 22 或控件宽度减 36 |
| 左侧强调条 | 宽 `2` | 从控件顶部 -3 延伸到控件底部 +3 |
| 复选框 | 使用原生复选框 | 不复制第二个开关 |
| 选中背景透明度 | `0.08` | 鼠标悬停时为 `0.16` |
| 未选中悬停透明度 | `0.16` | 仅鼠标悬停显示 |
| 选中左侧强调条透明度 | `0.75` | 选中时保持明显强调 |
| 悬停左侧强调条透明度 | `0.35` | 未选中但悬停时显示 |

标题背景的宽度必须跟随标题文字和控件宽度计算，不能写成固定的 550 像素，否则短标题会出现过长色块，四列中的主开关也会溢出。

### 主开关后的分隔底条

主开关后的分隔条由单独的滚动行承载：

- 行高：`5`。
- 纹理：`Interface/AddOns/GW2_UI/textures/hud/levelreward-sep.png`。
- 纹理裁剪：横向使用右半段纹理，即 `0.5, 1, 0, 1`。
- 纹理尺寸：约 `275 x 2`。
- 左偏移：8。
- 顶部偏移：5。
- 只在“主开关后面紧跟普通选项”时显示。

主开关后如果紧接另一个主开关，则不插入分隔条。主开关之后没有其他选项时，也不需要显示空分隔条。

## 单列、双列、三列、四列

### 通用规则

多列布局由连续选项上的 `gwPlusColumns` 触发：

```lua
local first = panel:AddOption("第一项", nil, {...})
local second = panel:AddOption("第二项", nil, {...})
local third = panel:AddOption("第三项", nil, {...})

first.gwPlusColumns = 3
second.gwPlusColumns = 3
third.gwPlusColumns = 3
```

项目中通常使用 `SetRow()` 封装：

```lua
local function SetRow(columnCount, ...)
    for index = 1, select("#", ...) do
        local option = select(index, ...)
        if option then option.gwPlusColumns = columnCount end
    end
end

SetRow(3, first, second, third)
```

必须遵守：

1. 同一行的选项必须在 `panel.gwOptions` 中连续。
2. 同一行的每个选项必须使用相同的列数。
3. 列数标记只影响当前连续区间，不会跨过标题或另一个未标记选项。
4. 不要把分组标题、主开关或按钮插入一个多列区间中。
5. 本规范只支持 2、3、4 列；不要使用 5 列以上。
6. 未设置列数，或设置为 `nil` / `1`，表示单列。

### 单列

单列用于长标题、长说明、文本输入、复杂下拉框、页面总开关和需要完整宽度的按钮。

| 项目 | 数值 |
|---|---:|
| 有效宽度 | `550` |
| 控件左坐标 | `8` |
| 普通控件高度 | `40` |
| 普通行高度 | `46` |
| 按钮实际高度 | `24` |
| 按钮行高度 | `40` |

示例：

```lua
local description = panel:AddOptionText("说明", "输入完整说明。", {...})
-- 不设置 gwPlusColumns，默认单列
```

### 双列

双列是最常用的紧凑布局，适合两个短标题的开关、滑块、下拉框或按钮。

```text
有效内容宽度：550
列间距：8
每列宽度：(550 - 8) / 2 = 271
第 1 列左坐标：8
第 2 列左坐标：287
```

玩家 PLUS 页面使用上述原生间距；其他 PLUS 页面未设置 `gwPlusColumnGap` 时，仍为每列 275、左坐标 8 和 283 的无间距布局。

示例：

```lua
local width = panel:AddOptionSlider("宽度", nil, {...})
local height = panel:AddOptionSlider("高度", nil, {...})
SetRow(2, width, height)
```

### 三列

三列适合短标题的布尔开关，以及三个状态、材质或显示方式选项。

```text
有效内容宽度：550
列间距：8
每列宽度：(550 - 16) / 3 = 178
第 1 列左坐标：8
第 2 列左坐标：194
第 3 列左坐标：380
```

经典示例是“框体 > 玩家 > 综合”中的前三个选项：

```lua
SetRow(3,
    grouped["PLAYER_AS_TARGET_FRAME_ALT_BACKGROUND"],
    grouped["player_CLASS_COLOR"],
    grouped["PLAYER_SHOW_PVP_INDICATOR"])
```

三列只适合短标题。标题宽度不足时，文字不会自动变成多行布局，可能会与相邻控件产生视觉拥挤。

### 四列

四列只适合非常短的开关或按钮，例如“离开”“计时”“准备”等短命令。

```text
有效内容宽度：550
列间距：8
每列宽度：(550 - 24) / 4 = 131.5
第 1 列左坐标：8
第 2 列左坐标：147.5
第 3 列左坐标：287
第 4 列左坐标：426.5
```

四列限制：

1. 不放长下拉框。
2. 不放文本输入框。
3. 不放颜色选择器。
4. 不放需要显示较长数值范围的滑块。
5. 只使用短标题，并在游戏内检查英文、中文和带前缀图标的最宽情况。

### 不完整列组

如果声明三列但只提供两个连续选项，渲染器仍按三列宽度计算，第三列会空出：

```lua
SetRow(3, first, second)
```

这不是自动的“两列布局”。需要两列时必须写 `SetRow(2, first, second)`。不要依赖渲染器自动重新分配宽度。

## 不同控件的列布局规则

### 布尔开关

布尔开关使用复选框和标题：

- 复选框沿用原生模板，不创建第二套复选框。
- 标题默认从控件左侧约 35 像素处开始。
- 多列时标题宽度按 `max(列宽 - 40, 40)` 限制。
- 双列最稳妥，三列适合短标题，四列只允许极短标题。
- 说明写入 tooltip，不在控件行中增加第二行描述。

### 滑块

多列滑块使用紧凑布局，当前规则如下：

| 部件 | 规则 |
|---|---|
| 左边缘 | 5 |
| 标题宽度 | 58 |
| 标题与滑块间距 | 6 |
| 数值输入框 | 列宽大于等于 240 时为 46，否则为 40 |
| 滑块宽度 | 根据剩余空间计算，最小 48 |
| 滑块与输入框间距 | 6 |
| 控件高度 | 40 |

建议：

1. 宽度和高度成对设置时使用双列。
2. 三列只用于短标题、短数值和不需要很长刻度文字的滑块。
3. 四列不要使用滑块，最小滑块宽度会造成输入框挤出列宽。
4. `decimalNumbers`、`min`、`max`、`step` 必须与输入框显示格式一致。

### 下拉框

多列下拉框使用紧凑布局：

- 左边缘：5。
- 标题宽度：58。
- 标题与下拉框间距：6。
- 下拉框宽度：`max(列宽 - 5 - 5 - 58 - 6, 80)`。
- 下拉框高度：25。

建议：

1. 双列适合大多数下拉框。
2. 三列只用于标题短、当前值短的下拉框。
3. 四列不使用下拉框；其最小宽度会超过玩家页面的 131.5 列宽。
4. 选项列表中较长的值通过下拉菜单展示，不要试图把完整说明写进控件标题。

### 文本输入

多列文本输入使用：

- 标题宽度：76。
- 标题与输入框间距：6。
- 输入框最小宽度：70。
- 控件高度：40。

文本输入推荐单列或双列。三列只能用于短字段；四列禁止使用，因为标题和最小输入框的总宽度已经超过单列可用空间。

### 颜色选择器

颜色选择器使用：

- 标题宽度：76。
- 标题与颜色按钮间距：6。
- 颜色按钮最小宽度：80。
- 控件高度：40。

颜色选择器推荐单列或双列，三列仅限标题很短的情况，四列禁止使用。

### 列表控件

列表控件通常需要比普通 40 高行更多的高度，且当前 GW2_UI_PLUS 多栏控件模板表没有为 `list` 提供专用的多栏模板。因此列表控件：

1. 默认使用单列。
2. 不设置 `gwPlusColumns`。
3. 不把列表和滑块、下拉框拼到同一行。
4. 如果必须扩展列表高度，应使用列表自身的 `entryHeight` 和 `maxVisibleRows`，不要压缩普通行高。

## 按钮布局规则

### 按钮类型

页面命令按钮使用 `AddOptionButton()`：

```lua
local reset = panel:AddOptionButton(
    "恢复默认",
    "恢复当前页面的所有设置，并把对应框体移回默认位置。",
    {
        callback = function()
            -- 执行实际动作
        end,
        isNegativeButton = true,
    }
)
```

按钮是命令，不是一个需要 `getter`、`setter` 和 `getDefault` 的布尔选项。按钮不应被“恢复默认”逻辑当成配置值处理。

### 单列按钮

单列按钮用于：

- 页面级恢复默认。
- 说明较长的操作。
- 需要明显强调的危险操作。
- 只有一个命令、没有可配对命令的页面。

尺寸：

- 有效宽度：550。
- 行高：40。
- 按钮实际高度：24。
- 上下各保留 8 像素。

### 双列按钮

双列按钮适合把两个相关命令放在同一行，例如：

```text
解锁/锁定                         重置位置
```

```lua
local mover = panel:AddOptionButton("解锁/锁定", "解锁后可以拖动框体。", {...})
local reset = panel:AddOptionButton("重置位置", "只把框体移回默认位置。", {...})
SetRow(2, mover, reset)
```

尺寸：

- 默认 PLUS 页面每列宽度：275；玩家 PLUS 页面每列宽度：271。
- 玩家 PLUS 页面两列之间保留 8 像素列间距。
- 行高：40。
- 每个按钮实际高度：24。
- 两个按钮必须有相同的垂直对齐方式。

### 三列、四列按钮

技术上按钮可以使用 `gwPlusColumns = 3` 或 `4`，但只在标题非常短时使用。按钮文字居中显示，列宽过小时更容易截断，因此：

- 常规命令最多双列。
- 四列只用于短到不会截断的命令。
- “恢复默认”通常使用单列，最多与“解锁/锁定”组成双列。

### 按钮颜色与危险样式

设置页面按钮分为两种视觉类型。按钮类型只决定视觉，不决定回调会修改哪些设置。

#### 普通操作按钮

普通操作按钮用于“解锁/锁定”“编辑”“试听”“打开管理窗口”等不会直接清空或恢复配置的命令。

普通按钮使用 `GwButtonTextTmpl`，该模板继承 `GwStandardButton`。当前皮肤规则如下：

| 状态/元素 | 规则 |
|---|---|
| 背景 | `Interface/AddOns/GW2_UI/textures/uistuff/button.png` |
| 禁用背景 | `Interface/AddOns/GW2_UI/textures/uistuff/button_disable.png` |
| 边框 | 沿用 `statusbarborderpixel.png` 和 `statusbarborderpixelvertical.png`，上下及左右各保留约 2 像素边框 |
| 正常文字 | 黑色，RGB `0, 0, 0` |
| 文字字体 | `DAMAGE_TEXT_FONT`，12 号；按钮模板的基础字体为 `SystemFont_Med1` |
| 正常悬停 | 使用 `button_hover.png` 纹理，通过 GW2_UI 的悬停动画显示 |
| 文字阴影 | 关闭，避免黑色按钮文字出现额外阴影 |

普通按钮示例：

```lua
local mover = panel:AddOptionButton(
    "解锁/锁定",
    "解锁后可以拖动框体；再次点击即可锁定。",
    {
        callback = function()
            ToggleHudMover(frameName)
        end,
    }
)
```

普通按钮不应自行创建一张纯色背景，也不应自行把文字设置成红色、绿色或金色。统一使用现有 `GwStandardButton` 皮肤，避免同一页面出现多套按钮风格。

#### 重置/危险按钮

下列按钮属于同一个“重置/危险按钮”视觉类型：

- “恢复默认”。
- “重置位置”。
- “重置位置与缩放”。
- “恢复本组默认”。
- 会清空历史、删除数据或不可逆修改配置的按钮。

这类按钮使用 `isNegativeButton = true`：

```lua
panel:AddOptionButton("恢复默认", "恢复当前页面全部设置和对应框体位置。", {
    callback = RestorePanelDefaults,
    isNegativeButton = true,
})
```

当前 `GwSkinNegativeButton()` 的实际视觉规则如下：

| 状态/元素 | 规则 |
|---|---|
| 正常背景 | 仍使用 `button.png`，但整体染为浅红色，VertexColor 为 `1, 0.84, 0.84` |
| 正常文字 | 深红色，RGB `0.55, 0.05, 0.05` |
| 正常边框 | 继续沿用普通按钮的边框纹理，不另换边框模板 |
| 鼠标悬停背景 | 使用 `button_hover.png`，悬停颜色为 RGB `1, 0.2, 0.2` |
| 鼠标悬停文字 | 浅白色，RGB `1, 0.96, 0.96` |
| 鼠标离开 | 恢复深红文字和浅红背景 |
| 禁用状态 | 使用 `button_disable.png`；控件禁用时沿用框体的禁用处理，不自行恢复为普通黑色按钮 |
| 文字阴影 | 关闭 |

重置/危险按钮仍然保持以下尺寸规则：

- 单列有效宽度：550。
- 默认 PLUS 页面双列每列宽度：275；玩家 PLUS 页面双列每列宽度：271。
- 玩家 PLUS 页面双列按钮之间保留 8 像素列间距。
- 滚动行高度：40。
- 按钮实际高度：24。
- 上下各保留 8 像素。

#### 两种按钮类型的对照

| 类型 | 背景 | 正常文字 | 悬停文字 | 典型用途 |
|---|---|---|---|---|
| 普通操作按钮 | `button.png` 原色 | 黑色 `0,0,0` | 继续使用普通悬停纹理 | 解锁、编辑、试听、打开窗口 |
| 重置/危险按钮 | `button.png` 浅红染色 | 深红 `0.55,0.05,0.05` | 浅白 `1,0.96,0.96` | 恢复默认、重置位置、清空数据 |

“恢复默认”和“重置位置”在视觉上属于同一类负面按钮，不能通过颜色推断它们的修改范围。它们的区别必须由按钮文字、tooltip 和回调明确规定：

| 按钮 | 视觉类型 | 实际修改范围 |
|---|---|---|
| 恢复默认 | 重置/危险按钮 | 当前页面全部设置 + 当前页面对应框体位置 |
| 重置位置 | 重置/危险按钮 | 只有当前框体的位置数据 |
| 重置位置与缩放 | 重置/危险按钮 | 当前框体位置 + 缩放值 |
| 其他普通按钮 | 普通操作按钮 | 只执行自身命令，不自动恢复设置 |

因此，不能因为两个按钮都使用红色样式，就让它们调用同一个 `Reset()` 函数。按钮的视觉归类相同，行为契约仍然完全不同。

必须通过按钮文字、tooltip 和回调明确说明实际行为：

- 只重置位置：按钮文字为“重置位置”。
- 重置页面设置和位置：按钮文字为“恢复默认”。
- 重置位置和缩放：必须明确写“重置位置与缩放”，不能简称为“重置位置”。

实现检查：

1. 普通操作按钮不得设置 `isNegativeButton = true`。
2. 所有重置、恢复、清空或删除类按钮必须设置 `isNegativeButton = true`。
3. `isNegativeButton` 只改变按钮皮肤，不负责执行恢复逻辑。
4. 恢复逻辑必须写在 `callback` 中，并根据按钮名称实现对应范围。
5. 不能用按钮颜色代替 tooltip；用户必须能从文字和说明看懂按钮会改什么。

## 恢复默认与重置位置

这是本规范中最重要的行为约束。按钮名称和实际回调必须一一对应，不能用同一个按钮名称表示两种行为。

### “恢复默认”的准确含义

按钮名称为 **“恢复默认”** 时，必须同时完成：

1. 恢复当前设置页面中的全部实际设置项。
2. 恢复该页面对应移动框体的位置。
3. 立即刷新当前页面中的所有可见控件。
4. 立即刷新依赖关系，包括禁用状态、透明度和可操作状态。
5. 立即重新应用可以在当前状态下应用的视觉和框体变化。

这里的“全部实际设置项”包括：

- 布尔开关。
- 滑块及其数值输入框。
- 下拉框。
- 文本输入。
- 颜色选择器。
- 当前页面注册的其他有 `getter`、`setter`、`getDefault` 的值型选项。

不包括：

- `AddGroupHeader()` 创建的标题。
- `AddSubGroupHeader()` 创建的子类标题。
- 只执行动作、没有配置值的普通命令按钮。
- “解锁/锁定”这类移动控制按钮本身。

### “恢复默认”的执行顺序

推荐执行顺序：

```text
检查战斗状态
    ↓
读取当前页面的全部配置项
    ↓
逐项取得 getDefault() 并写入 setter()
    ↓
执行每个选项对应的 callback()
    ↓
重置页面对应的移动框体位置
    ↓
刷新所有可见控件的显示值
    ↓
重新计算依赖关系
    ↓
更新实际框体布局
```

如果处于战斗锁定状态，涉及受保护框体的操作必须进入项目已有的战斗外队列，不能直接修改受保护框体。队列执行后仍然要完成控件刷新。

### 默认值来源

按钮回调不应重复硬编码一份默认值。每个设置项的默认值应由自己的 `getDefault()` 提供：

```lua
getDefault = function()
    return defaults.healthBarHeight
end
```

对于表值默认值必须复制表，不能直接把全局默认表引用写入 SavedVariables：

```lua
local value = option.getDefault()
if type(value) == "table" then
    value = GW.CopyTable(value)
end
option.set(value)
```

对于一个下拉框同时管理多个开关的情况，必须逐个恢复所有选项值，不能只恢复当前选中的一项。

### 控件即时刷新

恢复默认后，界面不能只修改 SavedVariables 而保持旧的控件显示。必须完成下列刷新：

| 控件 | 必须刷新 |
|---|---|
| 开关 | `SetChecked(get())` |
| 滑块 | 滑块位置和输入框文本 |
| 下拉框 | 当前选中项或菜单生成状态 |
| 文本框 | 当前文本 |
| 颜色选择器 | 当前颜色纹理 |
| 依赖项 | 启用/禁用状态、透明度、标题颜色 |

当前项目中可复用 `GW.RefreshSettingsPanel(panel)` 或 `ActionBarOptionsUtils.RefreshPanel(panel)`；如果页面有自定义依赖，还必须调用该页面对应的依赖刷新逻辑。

需要重载界面的设置仍然可以显示“需要重载”的提示，但不能因此跳过控件即时刷新。恢复默认只是把值恢复到默认，不等于自动替用户执行重载。

### “重置位置”的准确含义

按钮名称为 **“重置位置”** 时，只允许修改移动框体的位置数据：

- `point`。
- `relativePoint`。
- `xOfs`。
- `yOfs`。
- `hasMoved` 或等价的移动状态标记。

“重置位置”不得修改：

- 启用状态。
- 缩放值。
- 宽度和高度。
- 按钮显示状态。
- 文本、颜色、材质或下拉框值。
- 当前页面的任何其他设置。

位置重置完成后只需要：

1. 更新 SavedVariables 中的位置。
2. 清除移动框体锚点并重新锚定到默认点。
3. 清除 `isMoved` 状态。
4. 更新对应框体的当前显示位置。

### 按钮命名对照表

| 按钮文字 | 允许修改 | 禁止修改 |
|---|---|---|
| 恢复默认 | 当前页面全部设置 + 当前框体位置 | 其他页面设置 |
| 重置位置 | 当前框体位置 | 当前页面所有配置值 |
| 重置位置与缩放 | 当前框体位置 + 缩放 | 其他页面配置、尺寸、启用状态等 |
| 恢复本组默认 | 明确列出的本组配置 + 本组位置 | 未列入本组的其他设置 |

### 现有代码的迁移注意

新增代码必须优先参考 `Modules/Settings/HudMoverOptions.lua`：

- `restorePanel = true` 时使用“恢复默认”，恢复页面全部选项和框体位置。
- `restorePanel = false` 时使用“重置位置”，只调用位置重置逻辑。

不要复制下面这种语义冲突：按钮显示“重置位置”，回调却调用模块级 `Reset()`，同时重置模块配置和位置。若确实要重置模块配置与位置，按钮必须命名为“恢复默认”或“恢复本组默认”。

## 框体综合页面参考

“框体 > 玩家 > 综合”是多栏设置的基准案例。它不是复制一套新的原生设置，而是：

1. 读取 GW2_UI 已创建的 `player_general` 原生选项。
2. 删除已迁移到其他页面的选项。
3. 按 `GENERAL_OPTION_ORDER` 重新排列保留选项。
4. 新增 GW2_UI_PLUS 的普通玩家框体主开关。
5. 为连续选项设置 `gwPlusColumns`。
6. 通过 `Utils.InitializePanel(playerGeneral)` 重新构建滚动布局。

### 当前工作区中的实际顺序

当前 `Modules/UnitFrames/PlayerResources.lua` 的 `PrepareGeneralPanel()` 采用以下顺序：

```text
启用普通玩家框体                                  单列主开关
分隔底条                                          5 高
显示另一种背景材质 | 显示职业颜色 | PvP 指示器       三列
显示生命值数值                                    单列
生命条材质                                        单列
其他仍保留的原生选项                               单列
解锁/锁定 | 恢复默认                                双列按钮，不显示“位置”分类标题
```

前三个设置的三列标记来自：

```lua
SetRow(3,
    grouped["PLAYER_AS_TARGET_FRAME_ALT_BACKGROUND"],
    grouped["player_CLASS_COLOR"],
    grouped["PLAYER_SHOW_PVP_INDICATOR"])
```

当前源码对 `PLAYER_UNIT_HEALTH` 和 `playerFrameHealthBarTexture` 没有设置 `gwPlusColumns`，所以它们按单列处理。若未来产品设计要求它们变为双列，必须明确写成：

```lua
SetRow(2,
    grouped["PLAYER_UNIT_HEALTH"],
    grouped["playerFrameHealthBarTexture"])
```

并确认两个选项在 `playerGeneral.gwOptions` 中连续、顺序正确，随后重新初始化面板。不能只在文档或设计稿中标为双列而不修改列标记。

### 框体综合页面的主开关

当前页面的“启用”只控制普通玩家框体，不控制球状血条：

```lua
local normalPlayerFrame = playerGeneral:AddOption(
    "启用",
    "只控制普通玩家框体，不影响球状血条。",
    {
        getter = AB.IsNormalPlayerFrameEnabled,
        setter = AB.SetNormalPlayerFrameEnabled,
        getDefault = function() return true end,
        callback = function()
            AB.SyncPlayerHudEnabled()
            AB.ApplyNormalPlayerFrameVisibility()
        end,
        isMasterToggle = true,
    }
)
```

因此文档和按钮说明不能把它写成“启用所有玩家资源”或“启用球状血条”。页面描述、主开关 tooltip、恢复默认回调都要遵守这个边界。

### 框体综合页面的恢复默认

由于页面对应移动框体是 `GwPlayerUnitFrame`，页面底部的“恢复默认”必须包含：

- 综合页面所有值型选项恢复 `getDefault()`。
- `GwPlayerUnitFrame` 的位置恢复默认锚点。
- 所有控件立即显示默认值。
- 依赖 `HEALTHGLOBE_ENABLED`、`PLAYER_AS_TARGET_FRAME` 等条件的控件立即更新禁用状态。
- 需要重载的设置继续显示待重载提示。

页面中的“重置位置”如果单独存在，则只能把 `GwPlayerUnitFrame` 移回默认位置，不能修改“启用”、职业颜色、生命值显示、材质或任何其他选项。

### 目标、目标的目标和宠物综合页面规则

“框体 > 目标”“框体 > 目标的目标”和“框体 > 宠物”的“综合”页面沿用同一套边界：

1. 目标和宠物原生的“启用”保留主开关样式。
2. “目标的目标”的原生 `target_TARGET_ENABLED` 仍然使用原配置来源、回调、默认值和依赖，但在 PLUS 综合视图中以 `isMasterToggle = true` 的替代选项显示；原普通样式选项不重复显示。
3. 三个综合页的主开关下面保留原生 `masterToggleSeparator` 横向分隔线。
4. 页面已有移动控制时，底部“解锁/锁定”和“恢复默认”使用 `SetRow(2, mover, reset)` 放在同一行。
5. 这三个综合页面不显示 PLUS 添加的“位置”分组标题。
6. 只有页面原本已经有移动控制时才调整按钮布局；没有移动控制的渐隐、光环或其他页面不新增按钮。
7. 综合页面的其他目标、目标的目标和宠物设置项必须全部保留；本规则不改变渐隐和光环页面的内容。

其中“恢复默认”仍按当前页面全部设置加对应移动框体位置执行，并立即刷新控件和依赖状态；“解锁/锁定”只负责当前已有框体的移动状态。

对于由 PLUS 预先创建多个 `view.provider` 的页面，按钮必须同时追加到当前综合 view 的 `options`，并在 provider 中追加一条 `cols = {mover, reset}` 记录。只设置 `gwPlusColumns` 或只追加到面板的 `gwOptions`，不能改变已经生成的原生单列行。

## 编辑模式面板通用修改方法

本节规定以后修改任意编辑模式移动框体面板时必须遵循的通用方法。当前施法条只是已经完成的一份实例，用来说明“去掉什么、加什么、如何重新布局、恢复默认如何同步”；以后如果用户点名其他框体，必须按同样的流程重新确认，不得把施法条的控件和默认值直接复制过去。

编辑模式面板与“设置 > 框体”页面是两套界面。前者负责选中移动框体时的移动、尺寸和命令按钮；后者负责具体功能开关和配置值。两者可以共享配置和恢复接口，但不能混用控件引用或恢复范围。

### 1. 先拆分用户需求

每次修改编辑模式前，先把用户明确提出的内容写成一张目标表：

| 项目 | 必须记录的内容 |
|---|---|
| 目标框体 | 编辑模式显示名称、全局框体名、`mover.setting` 或其他稳定识别方式 |
| 去掉什么 | 要隐藏的原生控件、原生标题、原生按钮或原生分组；没有点名的原生内容默认保留 |
| 加什么 | 新控件名称、控件类型、顺序、范围、步长、默认值和配置键 |
| 怎么应用 | 修改哪个配置表、调用哪个现有 Apply 函数、需要同步哪些子框体或贴图 |
| 恢复什么 | 恢复默认按钮需要恢复的配置、位置、尺寸、缩放和即时刷新范围 |
| 明确不改什么 | 其他框体、其他页面、原生文件、SavedVariables 和外部插件 |

“用户没有点名”必须作为明确的保留项处理。不能因为控件结构相同，就自动给其他框体增加相同控件；不能因为需要隐藏某个目标的控件，就全局隐藏原生控件。

### 2. 找到实际生效入口

先检查 TOC 加载顺序和同名函数，确认最终执行的文件。当前项目的通用检查顺序是：

```text
GW2_UI_PLUS.toc
    ↓
实际加载顺序
    ↓
最终定义的 SetupMoverOptionPanel / RefreshMoverOptionPanel
    ↓
当前移动框体的 OnClick、OnShow 或刷新回调
```

当前施法条的实际入口是：

```text
Modules/ActionBar/ActionBar_Layout.lua
    SetupMoverOptionPanel()
    AB.RefreshMoverOptionPanel()
    SetNativeMoverResetHandler()
```

其他对象不一定使用这三个函数，必须以搜索结果和 TOC 为准。不能只改较早加载的同名函数，也不能假定修改了设置页面就会自动修改编辑模式面板。

### 3. 稳定识别目标，不按显示文字判断

必须使用框体名、`mover.setting`、父框体或项目已有的稳定标记判断目标。推荐先写专用判断函数：

```lua
local function IsTargetMover(mover)
    return mover and mover.setting == TARGET_MOVER_SETTING
end
```

刷新流程必须先区分三类：

```lua
local mover = settingsFrame.childMover
local barIndex = GetMoverBarIndex(mover)
local target = IsTargetMover(mover)

if barIndex then
    -- 已有动作条逻辑
elseif target then
    -- 本次用户点名对象的自定义逻辑
else
    -- 其他框体的原生逻辑
end
```

目标分支只能处理目标框体。其他分支必须继续保留原来的控件显示、原来的尺寸滑块、原来的坐标布局和原来的恢复回调。

### 4. 去掉原生控件的正确做法

“去掉”编辑模式控件通常表示对目标选中状态隐藏，不是删除控件，也不是修改 GW2_UI 原生模板：

```lua
options.nativeControl:SetShown(false)
```

处理顺序：

1. 找到目标控件的实际引用，例如 `options.scaleSlider`、`options.heightSlider`。
2. 只在目标分支设置 `SetShown(false)`。
3. 如果该控件还由原生逻辑通过 `optionScaleable`、`optionHeight` 或类似字段控制，必须同步关闭对应能力标记。
4. 切换到其他框体时重新根据其他框体的能力字段设置 `SetShown()`，不能沿用目标框体的隐藏结果。
5. 如果去掉的是原生标题或分组，必须确认它不会继续占用布局高度；不能只把文字设为空而留下空行。

如果用户要求“删除某个控件并用一个新控件代替”，实际动作是“目标分支隐藏原控件 + 目标分支创建新控件”。原控件仍然保留在内存中，以避免破坏原生面板结构。

### 5. 新增控件的正确做法

新控件必须放在目标专用的自定义容器中，例如：

```lua
local custom = CreateFrame("Frame", nil, options)
custom:SetSize(CUSTOM_WIDTH, CUSTOM_HEIGHT)
custom:SetPoint("TOPLEFT", options, "TOPLEFT", 0, -5)
custom:Hide()
options.gwPlusTargetOptions = custom
```

控件创建必须复用项目已有的控件工厂和视觉样式，不要为单个目标重新画一套滑块、输入框或按钮。每个新增配置控件都必须明确以下接口：

| 接口 | 要求 |
|---|---|
| 显示名称 | 与用户要求的文字一致，不自行改名 |
| 配置键 | 与设置页或现有模块使用同一份数据；不得建立重复 SavedVariables |
| 读取 | 从实际配置读取当前值 |
| 写入 | 先做范围限制和取整，再写入配置 |
| 默认值 | 使用现有 defaults 或目标设置项的 `getDefault()` |
| 应用回调 | 调用现有 Apply 函数，或调用目标模块公开的应用接口 |
| 刷新 | 打开、切换目标、恢复默认后同步滑块和输入框 |

滑块和输入框的通用数据流必须是：

```text
用户拖动滑块 / 提交输入框
        ↓
范围限制、取整、步长对齐
        ↓
写入唯一配置来源
        ↓
调用目标 Apply 函数
        ↓
更新目标外层框体和所有受影响的子框体
```

`OnValueChanged` 在 `refreshing` 状态下必须直接返回，避免仅仅刷新面板就反写 SavedVariables。按 Escape 只恢复输入框的显示值，不触发配置写入。

### 6. 修改尺寸时同步完整的视觉层级

不能只对目标外层框体调用 `SetSize()`。必须沿着目标框体的子层级检查：

```text
目标移动框体
    ├─ 主框体
    ├─ 进度条或内容框体
    ├─ 进度条内部贴图 / 状态条纹理
    ├─ 遮罩、填充值、动画贴图
    ├─ 延迟、提示、边框或高亮贴图
    └─ 移动框体背景和文字
```

每一层都要回答两个问题：

1. 它是否有独立的固定宽度、高度或基准尺寸？
2. 原生事件、动画或 `SetValue()` 是否会在用户修改后再次覆盖它？

如果有独立尺寸，必须在同一个 `ApplyTargetSize()` 中同步；如果原生事件会覆盖，必须在实际运行的目标实例上使用 `HookScript()` 或 `hooksecurefunc()`，在原生逻辑执行后重新应用自定义尺寸。

当前施法条暴露的典型问题是：

- 原生 XML 的默认宽高为 `176 x 15`。
- 黄色进度实际由 `progress.internalBar` 和结束动画 `highlight` 两层组成。
- 原生施法事件会持有已经设置到实例上的 `OnEvent` 函数引用。
- 因此只修改外层、只挂全局 mixin 表或只改一次初始化，都不能保证后续施法结束后仍然正确。

这套排查方式适用于任何以后点名的编辑框体，不只适用于施法条。

### 7. 重新布局时按“控件链”计算

目标面板增加或隐藏控件后，必须同时调整三个层级：

```text
自定义控件容器高度
        ↓
移动坐标区域锚点
        ↓
选项面板和编辑模式外层容器高度
```

推荐做法：

```lua
options.movers:ClearAllPoints()
options.movers:SetPoint(
    "TOPLEFT", custom, "BOTTOMLEFT", 0, -VERTICAL_GAP)
options:SetHeight(OPTIONS_HEIGHT)
container:SetHeight(CONTAINER_HEIGHT)
```

布局修改必须满足：

- 自定义控件之间不重叠。
- 移动坐标区域位于最后一个可见自定义控件下方。
- 恢复默认按钮仍在可见区域内。
- 目标分支的面板高度与容器高度同步调整。
- 切换到其他框体时，恢复该分支原来的锚点和高度。
- 每增加或去掉一行，都重新计算容器高度，不能只移动一个控件。

当前施法条示例为两行宽高控件：自定义容器 `170 x 90`，选项面板高度 `185`，外层容器和分隔线高度 `295`，移动坐标锚定在自定义容器底部下方 `5` 像素。其他对象必须根据自己的控件行数重新计算，不能直接复制这些数值。

### 8. “恢复默认”必须先确定恢复范围

按钮文字决定行为边界：

| 按钮文字 | 允许恢复 | 不允许恢复 |
|---|---|---|
| 恢复默认 | 当前点名对象明确列出的配置 + 该对象位置 + 明确列出的尺寸/缩放 | 其他对象、其他页面和未列出的配置 |
| 重置位置 | 当前对象位置和移动状态 | 启用、尺寸、缩放、材质、颜色和其他配置 |
| 恢复本组默认 | 需求中明确列出的本组配置和本组位置 | 未列入本组的任何配置 |

当用户要求编辑模式的“恢复默认”与设置页保持一致时，不能在编辑模式按钮里复制一套默认值。应导出目标专用的恢复接口，让编辑模式传入刷新回调：

```lua
local function RestoreTargetDefaults(onComplete)
    -- 读取目标设置页面的选项和 getDefault()
    -- 恢复目标位置
    -- 处理战斗外队列
    -- 刷新设置页和目标编辑面板
    return true
end
```

恢复接口的标准执行顺序：

```text
确认目标对象和目标页面
        ↓
检查 InCombatLockdown()
        ↓
逐项读取 getDefault() 并调用 setter / callback
        ↓
只恢复目标对象的位置数据
        ↓
重新应用目标尺寸、视觉和缩放约束
        ↓
刷新设置页、依赖状态、自定义控件
        ↓
执行 onComplete()
```

战斗中必须进入已有的战斗外队列。恢复完成后至少要刷新：

- 目标设置页的开关、滑块、输入框和依赖状态。
- 编辑模式自定义控件的当前值。
- 目标框体的位置、尺寸、子框体和视觉元素。
- 目标的固定缩放或其他明确的约束。

如果目标页面尚未创建，恢复接口可以动态查找；如果目标页面不存在，必须返回失败，由目标分支决定是否调用原生恢复回调。不能静默声称已经恢复成功。

### 9. 恢复按钮的目标分支写法

原生恢复按钮只能在目标对象分支替换：

```lua
local function SetTargetResetHandler(options, mover)
    if not options or not options.default then return end
    if not IsTargetMover(mover) then
        options.default:SetScript(
            "OnClick", GW.ResetMoverFrameToDefaultValues)
        return
    end

    options.default:SetScript("OnClick", function()
        local restore = addonTable.RestoreTargetDefaults
        if restore and restore(RefreshTargetPanel) then return end
        if GW.ResetMoverFrameToDefaultValues then
            GW.ResetMoverFrameToDefaultValues(options.default)
        end
    end)
end
```

如果原生恢复按钮本身只代表“重置位置”，而用户要求的是“配置 + 尺寸 + 位置”，必须使用目标恢复接口；不能让按钮文字保持“恢复默认”却只调用原生位置重置函数。

### 10. 当前施法条作为通用方法示例

当前施法条需求可以按下表复用为其他对象的填写模板：

| 需求字段 | 施法条实例 |
|---|---|
| 目标 | `GwCastingBarPlayer` / `castingbar_pos` |
| 去掉 | 原生“缩放”、原生“高度” |
| 增加 | “宽度”“高度”两个自定义滑块和输入框 |
| 配置 | `GW2_UI_PLUS_ActionBarSV.castbarWidth/castbarHeight` |
| 范围 | 宽度 `100-600`；高度 `10-100` |
| 默认值 | 宽度 `300`；高度 `15` |
| 应用 | `AB.ApplyCastbarSize()`，并同步进度条内部贴图、遮罩和动画贴图 |
| 恢复 | 启用、跳数、高级施法条、法术队列、宽度、高度、位置、固定缩放 `1` |
| 其他对象 | 不增加施法条宽高，不隐藏原生控件，不替换原生恢复逻辑 |

以后修改别的框体时，只替换这张表中的“目标、去掉、增加、配置、范围、默认值、应用、恢复”字段；流程、分支隔离、刷新顺序和禁止事项保持不变。没有明确填写的字段不得擅自增加。

### 当前编辑模式面板最终尺寸

编辑模式移动面板使用固定的区域宽度和内容区宽度，不能只增加外层宽度而保留旧的内部控件尺寸：

| 状态 | 区域宽度 | 内容区宽度 |
|---|---:|---:|
| 未展开 | `240` | `220` |
| 展开左边 | `240` | `220` |
| 展开右边 | `240` | `220` |

展开后的总宽度为 `480`，左侧和右侧各占 `240`。中间分隔线位于左侧区域右边界，即 `X = 240`。编辑面板外层和顶部拖动框必须同时使用对应的总宽度。

左侧移动控件的排版规则：

| 控件 | 尺寸或规则 |
|---|---:|
| 普通选项行、移动区域、恢复默认按钮 | 宽 `220` |
| 选项标题可用宽度 | `200` |
| 宽度/高度滑轨 | 宽 `170`，右侧保留数值输入框 |
| 锚点标签 | 宽 `30`，`屏幕` 和 `框体` 必须保持单行 |
| 锚点下拉框 | 每个宽 `77`，两列间隔 `6` |
| 过滤标签 | 宽 `50` |
| 过滤下拉框 | 宽 `170`，从标签右侧延伸到内容区右边界 |

锚点标签不得通过换行来适应窄宽度；如果文字放不下，应适当缩小下拉框，而不是压缩标签或改变内容区宽度。“过滤”后的下拉框必须使用内容区剩余宽度，不能继续使用原生 `125` 宽。

右侧布局区域的外层宽度为 `240`，主要内容宽度为 `220`。布局说明和专精下拉框使用 `220` 宽，布局下拉框使用 `210` 宽，新建和删除按钮各使用 `104` 宽。所有控件必须在右侧区域内保持可见，不得沿用展开前的 `180` 起点或宽度。

### 11. 通用验收清单

- [ ] 目标框体使用稳定的实例名、设置键或父框体识别。
- [ ] 只有目标分支隐藏了点名的原生控件。
- [ ] 未点名的原生控件、标题和按钮仍然存在。
- [ ] 新控件只出现在目标面板，并使用已有控件样式。
- [ ] 新控件有唯一配置来源、范围、步长、默认值和 Apply 回调。

## 实现清单

新增或修改一个设置页面时，按下面顺序检查：

### 页面顶部

- [ ] 已设置页面主标题，20 号字体。
- [ ] 已设置页面小标题，12 号字体。
- [ ] 已设置一句话页面描述，12 号暖灰色字体。
- [ ] 主标题、小标题、描述没有重复表达同一内容。
- [ ] 顶部文字在中英文环境下不会溢出。

### 内容和分组

- [ ] 内容总宽按 550 计算，行宽按 566 计算。
- [ ] 分组标题使用 `AddGroupHeader()`，子类标题使用 `AddSubGroupHeader()`。
- [ ] 分组标题使用 `LightHeader` 浅金色文字、白色 `0.65` 透明度分隔线和白色 `0.85` 透明度左侧强调块。
- [ ] 子类标题使用 `LightHeader` 浅金色文字和白色 `0.45` 透明度分隔线，不增加整行背景。
- [ ] 没有把 `groupHeaderName` 误当成可见标题。
- [ ] 标题后的 8 像素间距没有被手动重复添加。
- [ ] 普通行保持 46 高，标题/按钮/主开关行保持 40 高。

### 主开关

- [ ] 主开关使用 `isMasterToggle = true`。
- [ ] 主开关独占一行。
- [ ] 主开关后有普通选项时显示 5 高分隔行。
- [ ] 主开关背景和左侧强调条使用现有样式，不复制第二套纹理。
- [ ] 主开关的 tooltip 清楚说明它控制的范围。

### 多栏

- [ ] 同一行的选项在 `panel.gwOptions` 中连续。
- [ ] 同一行的选项使用相同的 `gwPlusColumns`。
- [ ] 默认 PLUS 页面按无间距计算；玩家页面设置 `panel.gwPlusColumnGap = 8`。
- [ ] 玩家双列按 271，三列按 178，四列按 131.5 计算。
- [ ] 玩家页面列起点使用 `8 + (column - 1) * (width + gap)`，没有按 `550 / 列数` 直接计算。
- [ ] 非玩家 PLUS 页面没有被误设列间距，继续保持原有无间距布局。
- [ ] 四列中没有下拉框、文本框、颜色选择器或长标题滑块。
- [ ] 需要单列的长控件没有被强行压入多列。

### 按钮

- [ ] 单个页面级操作使用单列按钮。
- [ ] 解锁/锁定与重置位置等成对操作使用双列按钮。
- [ ] 玩家页面的双列、三列、四列按钮均使用面板级 8 像素列间距。
- [ ] 按钮实际高度为 24，按钮行高度为 40。
- [ ] 危险操作使用 `isNegativeButton = true`。
- [ ] 按钮文字与回调行为完全一致。

### 默认值和位置

- [ ] “恢复默认”恢复当前页面全部设置和对应框体位置。
- [ ] “恢复默认”逐项使用 `getDefault()`，没有复制第二份默认值。
- [ ] “恢复默认”会刷新所有控件和依赖状态。
- [ ] “重置位置”只修改位置，不修改任何页面设置。
- [ ] 位置重置包含锚点、偏移量和移动状态标记。
- [ ] 战斗锁定时使用已有的战斗外队列。
- [ ] 当前页面不会重置其他页面或其他框体。

### 参考验证

完成代码后至少检查：

1. 设置页面打开时没有控件重叠或横向溢出。
2. 主开关切换后，分隔底条和后续行位置不跳动。
3. 双列、三列、四列在滚动和刷新后仍保持同一行。
4. 恢复默认后，滑块数值、下拉框文本、开关状态和依赖灰度都立即更新。
5. 重置位置后，页面其他值保持用户修改前的状态。
6. 页面关闭再打开后，设置值和框体位置仍然正确。
