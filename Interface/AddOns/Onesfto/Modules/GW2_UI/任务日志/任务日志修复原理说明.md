# GW2_UI 任务日志排版修复原理说明

## 1. 发现问题
在怀旧服（Classic Era）中文客户端下，使用 GW2_UI 美化任务日志面板（Quest Log）时，面板顶部的以下三个元素会发生严重的文字重叠和排版错乱：
- **“全部”按钮（展开/折叠全部任务）**
- **原生“追踪任务”复选框**
- **任务数量显示（例如“任务: 8/20”）**

## 2. 根本原因分析
通过分析 `GW2_UI/Games/Classic/Immersive/Skins/questLog.lua` 代码，发现问题由以下几点导致：
1. **硬编码的偏移量**：GW2_UI 将“全部”按钮（`QuestLogCollapseAllButton`）强制通过死坐标位移到了 `TOPLEFT, -45, 7`，而“全部”在中文环境下的文本渲染范围超出了原本 16x16 的图标大小。
2. **错误的左对齐逻辑**：原版暴雪界面的任务数量本应该在右侧，但 GW2_UI 将任务数量（`QuestLogQuestCount`）错误地移到了左边，并紧贴“全部”按钮，导致中文字体溢出并相互覆盖。
3. **原生追踪按钮干扰**：暴雪原生的“追踪任务”复选框（`QuestLogTrack`）会伴随 `QuestLogCollapseAllButton` 进行相对定位。另外，整合插件（如 NDui）会渲染复选框底图，暴雪 C 代码每次刷新（`QuestLog_Update`）也会强行将其显示，导致普通的 `Hide()` 和 Lua 层面的拦截失效，进而造成拥挤。

## 3. 修复方案

我们修改了 `Games/Classic/Immersive/Skins/questLog.lua`，并进行了如下排版重构，完美还原暴雪原生逻辑：

### A. 重新定位“全部”按钮
去除了原有的固定位移，将其正确地锚定在任务列表背景框的左上角。
同时将 Y 轴偏移量从 5 增加到 9，以保证它与原生的追踪按钮保持绝对的横向水平对齐。
```lua
QuestLogCollapseAllButton:ClearAllPoints()
QuestLogCollapseAllButton:SetPoint("BOTTOMLEFT", QuestLogListScrollFrame.backdrop, "TOPLEFT", 2, 9)
```

### B. 还原任务数量到右侧
取消了 GW2_UI 将任务数量挤在左边的逻辑，将其像暴雪原生 UI 一样，放置在列表背景框的右侧，并且同样将 Y 轴抬高对齐。
```lua
hooksecurefunc('QuestLog_Update', function()
    QuestLogQuestCount:ClearAllPoints()
    QuestLogQuestCount:SetPoint('BOTTOMRIGHT', QuestLogListScrollFrame.backdrop, 'TOPRIGHT', 0, 9)
end)
```

### C. 物理放逐“追踪任务”复选框
既然用户认为原生的“追踪任务”冗余且影响美观，且 C 代码会强制渲染它，我们采取了“将其定点到屏幕外”的绝对隐藏策略：
```lua
-- 暴雪底层的追踪复选框叫做 QuestLogTrack
if QuestLogTrack then
    QuestLogTrack:Hide()
    QuestLogTrack:SetAlpha(0)
    QuestLogTrack:ClearAllPoints()
    QuestLogTrack:SetPoint("BOTTOMLEFT", UIParent, "TOPLEFT", -9999, 9999)
end
```
*注：之前误将其当作 `QuestLogTrackTracking`（仅内部贴图），现已更正为主体框体 `QuestLogTrack`。*

## 4. 修复结果
经过上述调整，任务面板顶部空间得到了完美释放。
- 最左侧为：`▼ 全部`
- 最右侧为：`任务: 8/20`
- 两者在 Y 轴完美对齐，中间不再有任何杂乱的原生控件遮挡。
