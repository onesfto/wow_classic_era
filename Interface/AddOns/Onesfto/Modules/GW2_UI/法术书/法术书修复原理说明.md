# GW2_UI 法术书底层 Bug 修复原理说明

本文档详细解释了为什么我们需要直接修改插件源码中 `Games/Classic/Character/spellbook.lua` 文件，以及它是如何解决怀旧服环境下法术书的核心崩溃问题的。

## 一、 背景与现象
在怀旧服使用 GW2_UI 时，法术书模块存在两个致命的交互问题：
1. **法术点击失效（无法施放）**：部分中文环境法术（尤其是附带“等级”的法术），在鼠标左键点击时毫无反应，或触发 UI 报错。
2. **翻页状态丢失（自动跳回）**：在法术书中点击下一页时，由于后台事件刷新，页面会频繁跳回第一页，甚至导致翻页按钮置灰卡死。

## 二、 根本原因（Root Cause）
1. **法术标识符的不兼容与 API 变更**：原版 GW2_UI 构建的安全动作按钮依赖特定的 `spellID` 属性调用（`CastSpellByID`）。但在 1.15 版本怀旧服中，`CastSpellByID` 存在 Bug（要么施放最高级，要么对带有特定子等级的法术毫无反应）。不仅如此，暴雪底层的安全动作按钮（`SecureActionButtonTemplate`）在较新版本中对 `AnyUp`（鼠标抬起）事件采取了严格的静默拦截机制，导致按钮即使获得了正确的属性也无法触发施法动作。
2. **状态推算的脆弱性**：原作者对于法术书翻页（上一页/下一页）的判断，过度依赖简单的 `IsVisible()` 判断逻辑，且触发条件不够严谨。当游戏后台派发 `SPELLS_CHANGED` 事件引发页面重绘时，所有页面可能处于瞬时全黑状态，导致当前页码被强制重置为 `currentPage = 1`。

## 三、 为什么采用“直接修改源码”方案？
常规的插件修复思路是写一个独立的 Lua 补丁去外挂劫持原插件行为，但在此场景下不可行：
1. **Taint（权限污染）限制**：法术书点击与翻页框架使用的是暴雪底层的安全模板（`SecureHandlerClickTemplate` 和 `SecureActionButtonTemplate`）。第三方 Lua 补丁一旦在运行时动态干预这些受保护的框架环境，必定会触发战斗环境下的 Taint 报错。
2. **最佳实践**：唯一绝对安全且稳定的解法，是**直接修改 GW2_UI 的原始代码**，让框架在生成之初就处于正确的逻辑下。

## 四、 具体修复逻辑（Suggested Fix）

在 `spellbook.lua` 中进行了两处“外科手术式”的代码替换：

### 1. 安全动作按钮底层重构（解决点击失效）
*   **重构点 1（事件监听）**：将法术按钮的点击事件由 `RegisterForClicks("AnyUp")` 扩展为 `RegisterForClicks("AnyUp", "AnyDown")`。这成功绕开了 `SecureActionButtonTemplate` 针对抬起事件的默认静默拦截黑洞，并让施法响应变得如同官方动作条一样在“按下”瞬间触发，手感更丝滑。
*   **重构点 2（精准字符串匹配）**：彻底抛弃存在解析 Bug 的 `/cast` 宏机制，回归最底层的 `type="spell"` 属性。我们通过精确拼接出与暴雪底层数据库 100% 匹配的法术字符串（严格保留如 `"寒冰箭(等级 1)"` 中的所有空格），直接交由底层 `CastSpellByName` 进行施法，彻底解决了 `spellID` 在多级法术上的兼容灾难。

### 2. 状态阻断与强制属性刷新（解决翻页跳回）
*   **重构点**：在 `updateSpellbook` 翻页执行的沙盒代码中，对目标页面索引（`targetPage`）的赋值逻辑增加了“状态打断”机制。
*   **修复原理**：暴雪的安全属性环境（SecureHandler）有一个特征，如果多次 `SetAttribute("currentPage", x)` 赋值相同时，可能会被底层优化掉而不触发 `_onattributechanged` 回调。为了确保翻页动作在极端刷新情况下绝对执行，我们在每次翻页前，强制写入一个脏状态 `SetAttribute('currentPage', 0)`，再赋予真正的目标页码。这种“强制破防”手段完美规避了翻页死锁。
